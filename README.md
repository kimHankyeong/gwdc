# Sepolia 감사 기록 보일러플레이트

Solidity 계약 하나로 정책 해시와 거래 해시를 Sepolia에 기록하고 검증합니다. 앱·DB 연동 및 실제 결제 없이 체인만 테스트합니다. 자체 블록체인 노드를 구축하는 프로젝트는 아닙니다.

## 실행

Node.js 24에서:

```powershell
npm ci
npm test
Copy-Item .env.sepolia.example .env.sepolia
# .env.sepolia에 테스트 전용 개인키 설정 및 지갑에 Sepolia ETH 확보
npm run test:sepolia
```

기존 `.env.sepolia`가 있다면 복사 단계는 생략합니다. HTTPS RPC와 Sepolia 체인 ID `11155111`만 허용합니다. 키 파일은 Git에서 제외합니다.

## 계약과 검증

- `recordPurchase(bytes32 purchaseId, bytes32 policyHash, bytes32 recordHash)`
- 배포자만 호출 가능하며 빈 해시·중복 ID는 거절합니다.
- ID의 중복 여부를 상태에 저장하고 두 해시는 `PurchaseRecorded` 이벤트에 기록합니다.
- 스크립트는 식별 정보가 없는 고정 테스트 데이터와 임의 salt를 해싱합니다. 원문 데이터와 salt는 체인에 전송하지 않습니다.
- 배포 → 기록 → 성공 영수증·이벤트·해시 대조 → 중복·비인가 호출 거절을 검사합니다. 거절 검사는 `eth_call`로 수행합니다.

`state/`의 로컬 체크포인트에 서명된 트랜잭션을 전송 전에 저장합니다. 같은 폴더에서 재실행하면 기존 배포·기록을 확인합니다. 신규 테스트는 명시적으로 새 요청 ID를 지정하세요. 보고서는 블록 포함과 최종 확정을 구분합니다.

## 거래 안전장치 (v2)

- `TRACK_AUDIT_REQUEST_ID`가 같은 실행은 동일한 체크포인트와 서명 거래를 재사용합니다. 재시도 중 ID를 바꾸지 마세요. 다른 ID로 같은 내용을 기록하는 것은 새로운 거래로 허용합니다.
- 같은 PC에서 동일 지갑의 동시 실행을 잠급니다. 강제 종료로 잠금이 남으면 오류에 나온 경로에서 실행 중인 프로세스가 없는지 확인한 뒤 잠금만 제거합니다. 다른 PC나 외부 지갑 프로그램까지 잠그지는 못하므로 이 지갑은 테스트 전용으로 사용합니다.
- 서명자·체인·nonce·목적지·호출 인자·전송 금액(0 ETH)을 방송 전에 검사합니다. 원문·salt·해시가 달라지면 전송하지 않습니다.
- 배포 코드와 실제 계약 코드도 대조합니다. 코드가 바뀌었다면 새 요청 ID로 새 계약을 배포해야 합니다. 이전 v1 계약과 증거는 그대로 보존합니다.
- 거래별 최대 수수료는 `0.002 Sepolia ETH`, 최대 가스는 `2,000,000`입니다. 상한은 `scripts/audit-safety.mjs`에서 확인할 수 있습니다.
- 일시적 RPC 오류는 최대 3회 시도합니다. 채굴 대기는 45초이며 미확정 거래는 같은 ID로 재실행합니다. nonce 소모·대체 의심·실패 영수증은 수동 확인 대상으로 중단하며 자동으로 새 nonce를 쓰거나 수수료를 올리지 않습니다.
- 보고서의 `included`는 블록 포함, `finalized`는 RPC의 최종 확정 블록까지 확인한 상태입니다. 같은 요청을 재실행하면 블록 해시·영수증·최종 확정 여부를 다시 검사합니다. RPC 하나의 응답을 신뢰하므로 독립적인 합의 검증은 아닙니다.
- 합계·예산·안전한 정수 범위·KRW 통화·허용 필드를 검사합니다. 리뷰 증빙 기능이 없으므로 리뷰 필수 정책은 거절합니다. 결제·실제 구매·원문의 진실성을 증명하지 않습니다.
- 계약의 `setPaused(bool)`로 기록을 중지할 수 있습니다. `transferOwnership(address)` 후 새 소유자가 `acceptOwnership()`해야 권한이 이동합니다. 완전히 분실된 키의 복구나 이미 유출된 키와의 경쟁을 해결하는 기능은 아닙니다.

체크포인트는 임시 파일 쓰기·동기화 후 교체하고 이전본을 `.bak`에 보관합니다. `state/`의 원문·salt·서명 거래와 `.env.sepolia`는 비공개이며 별도의 접근 통제된 백업도 유지해야 합니다. 로컬 백업만으로 디스크 분실까지 복구할 수는 없습니다. 손상된 체크포인트는 자동으로 과거 백업으로 되돌리지 말고 온체인 상태와 대조하세요.

`npm test`는 서명·원문 변조, 수수료, 입력 검증, 잠금 경쟁, RPC 재시도, nonce 대체, 블록 재구성, 소유권 이전과 일시 중지를 검사합니다. 잠금 경쟁 검사는 200개 시도에서 1개만 진입하는지 확인하는 것이며 전체 서비스 200명 부하 시험은 아닙니다.
