## 수정한 결함
- HTML seller.name을 허용 판매처 신원으로 인정하지 않음. 검증된 신원이 없으면 판매처 제한을 통과하지 못함.
- 감사 readiness를 견적 준비, 실행, Worker 차감 전에 확인. 오래된 heartbeat도 차단하는 회귀 검증 추가.
- 재개 문맥에 조건 승인·기존 평가·질문 포함. Tool별 단계와 결과 구조 검증. 잘못된 재개 요청은 대기 상태를 바꾸지 않음.
- 검색/외부 자료/감사 오류는 추가 추론 전에 실행 중단. 모의 후보·성공 fallback을 금지.
- 검색 HTTP 200의 잘못된 JSON 구조를 빈 결과로 취급하지 않음. 페이지 cursor는 query·사용자/run/input 버전에 바인딩.
- 외부 응답 본문 크기를 읽는 도중 제한. 정책 관리 연결 실패는 한국어 오류로 표시.
- raw JSON과 ID 입력 대신 폼, 후보 카드, 정책 요약, 명시적 승인 제공. 오류 시 입력 보존, 편집 도중 이탈 차단, 편집 세션 복원 제공.
- 만료된 최초 견적도 갱신·재승인 가능. 거래 중 정책은 읽기 전용이며 별도 편집 화면에서만 새 버전 발행.

## 검증 한계
- Brave 키와 Sepolia RPC/서명자 설정이 없어 실제 검색→모의 영수증→실제 체인 확정 전체 경로는 검증하지 못했다. 테스트의 후보·readiness·감사 완료 fixture는 외부 연동 성공 증거가 아니다.
- 후보/최종 승인/영수증의 정상 데이터 화면은 코드·통합 테스트 범위이며, 이번 실서비스 브라우저 E2E는 검색 미연결에서 중단됐다.
- 판매처 신원 adapter, JS-only 상품 자료, 리뷰 진위, 배송 속도 근거는 미지원이다. 정책이 해당 근거를 요구하면 차단한다.
- 정책 통화 선택은 범용이지만 현재 원본 온체인 감사 v1은 KRW 단일 품목·리뷰 비필수만 지원한다. 다른 통화는 별도 장부 준비 및 감사 확장이 필요하며 성공을 가장하지 않는다.
- 제공사 prompt cache hit 100%는 보장할 수 없다. 고정 정책 prefix와 앱 캐시를 사용하며 강제 cache-only 요구는 계약 부재로 차단한다.
- 200개 동시 조회 검증은 5000명 사용자/200명 동시 구매의 운영 부하 검증이 아니다.
- QA harness의 정책 관리·거래 서비스는 테스트용 동일 프로세스다. 운영은 별도 OS 계정, 읽기 전용 정책 mount/ACL, 역할별 DB 계정이 필요하다.
