# Glass UI 및 실제 연동 QA 상태

- UI: PC 반투명 사이드바·패널, 모바일 하단 유리 탭, 둥근 입력/승인 컨트롤. 기존 TypeScript 기능과 정책 잠금 유지.
- 접근성: 최소 44px 터치 영역, 모바일 입력 16px, safe-area, 투명도/동작 줄이기 및 대비 강화 설정, backdrop-filter 미지원 대체 배경.
- 반응형 독립 검수: 1440×1000, 390×844, 320×740 설정에서 가로 넘침·글자 잘림 없음. 두 모바일 크기 모두 마지막 푸터와 고정 탭 사이 약 16px 여백 확인.
- 탭 이동 시 페이지 맨 위로 이동해 이전 화면 스크롤 위치가 새 화면에 남지 않도록 수정.
- 빌드 통과, Node 10 + Python 8개 회귀 테스트 통과.
- 스크린샷: Codex 시각화 폴더의 glass-desktop.png, glass-mobile.png, glass-mobile-bottom.png, glass-320.png, glass-320-bottom.png.
- 정적 디자인: opendesign/mockups/purchase-workspace/glass-{purchase,policy,history}.html. 기존 디자인 파일 보존.

## 실제 연동 — 설정 대기, 성공 미확인

현재 로컬 설정에서 BRAVE_SEARCH_API_KEY, SOURCE_ALLOWED_HOSTS, TRACK_RPC_URL, TRACK_VERIFY_RPC_URL, TRACK_CHAIN_PRIVATE_KEY가 비어 있다. 키·개인키는 출력하거나 문서에 기록하지 않는다. 사용자에게 로컬 .env 설정을 요청했다.

브라우저 QA harness가 실제 검색 allowlist를 사용하도록 수정했다. QA_REAL_AUDIT=true로 명시적으로 시작하면 실제 AuditWorker readiness와 작업 처리를 활성화한다. 준비 여부를 fixture로 대체하지 않는다. 이 모드는 Sepolia 테스트 지갑의 ETH를 사용한다. harness는 임시 모의 장부를 만들며 운영 계정 격리 검증 용도가 아니다.

설정 완료 뒤 필요한 검증:
1. 실제 Brave 검색 응답, 원문 출처/수집 제한, 후보 선택.
2. 실제 Kiln Tool Calling으로 조건·정책 평가, 사용자 승인, 모의 주문의 한 번만 차감.
3. 서로 다른 두 HTTPS RPC의 Sepolia chainId와 테스트 잔액 확인.
4. 실제 감사 전송, receipt 성공, 독립 RPC 확인, 영수증의 체인 상태 표시.
5. 재시도/새로고침에서 중복 주문·감사 방지 및 실패 안내.

현재 검색→주문→Sepolia E2E는 미검증이다. iOS Safari 실기기 테스트도 수행하지 않았으며 Chromium 반응형 검증 결과다. 웹 구현은 iOS 네이티브 Liquid Glass 자체가 아닌 해당 스타일의 웹 구현이다.

디자인 기준: [Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials), [Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass).
