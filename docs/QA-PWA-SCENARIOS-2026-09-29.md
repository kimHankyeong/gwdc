- 배포: `dpl_HdoQAVqNtXLnQLFbu1e5fm8wKDUH`, https://gwdc-team11.vercel.app (Vercel Ready 및 alias 확인).
- 결론: PWA 배포 및 PC·모바일 화면 검증 완료. 통제된 공격 10건은 차단됐다. **구매 시나리오 4건은 모두 최종 발주 미완료**다. 추가 입력·검색 장애·감사 미설정이 남아 있다.

## 구매 시나리오 4건

금액은 사용자 확정값이다. 견적 가격·세부 수량·시공 면적·납기는 임의로 만들지 않았다. 각 계정의 테스트 정책 한도와 모의 잔고를 해당 예산으로 설정했다.

| 요청 | 예산 | 실제 관찰 | 판정 |
|---|---:|---|---|
| 게이밍 컴퓨터 맞추기 | 5,000,000원 | Qwen이 `게이밍 컴퓨터`, 수량 1의 조건을 제안. 후보 선택·모의 단가·배송비 입력을 요청. 독립 검색 재호출은 실패 | `NEEDS_INPUT`, 영수증 0 |
| 짜장면 장사 투자 | 10,000,000원 | 구체 구매 항목·제외 조건·필수 조건 질문. 독립 검색 실패 | `NEEDS_INPUT`, 영수증 0 |
| 도배, 인력·종이만 | 15,000,000원 | 조건 제안 이후 실제 검색 실패 | `ACTION_REQUIRED / SEARCH_UNAVAILABLE`, 영수증 0 |
| 대학교 무대 디자인 | 50,000,000원 | 조건 제안 이후 실제 검색 실패 | `ACTION_REQUIRED / SEARCH_UNAVAILABLE`, 영수증 0 |

- 검색 실패를 생성 상품·가짜 가격으로 채우지 않았다. 네 요청은 검증 후 취소했다.
- PC·창업·시공·무대는 복수 품목 또는 서비스 계획이다. 현재 감사 v1 및 견적은 **단일 품목**이므로 부품 호환성, 인건비+자재 합산 견적, 공정·일정, 여러 판매처 일괄 발주를 지원한다고 볼 수 없다.
- 한 품목을 선택하고 사용자가 모의 금액을 입력한 뒤 조건 승인과 최종 승인이 필요하다. 현재 Sepolia 감사 Worker가 준비되지 않아 최종 주문은 차단된다.
- 앱 사용에 적합한 수준으로 판단하려면 실제 검색 안정화, 다품목/서비스 견적 계약, 감사 실행 환경을 먼저 해결해야 한다. 이번 결과는 구매 성공 4건이 아니다.

## 시스템 공격 5건

| ID | 공격 입력/행동 | 확인한 차단 근거 |
|---|---|---|
| S1 | 메타데이터·loopback 주소를 허용 호스트에 넣어 SSRF 시도, `file:` 접근 | 허용 목록을 통과해도 `UNSAFE_SOURCE_ADDRESS`, 파일 스킴 거절. 외부 요청 전 차단 |
| S2 | 다른 사용자 소유 요청 ID 조회 | `NOT_FOUND` |
| S3 | 요청 ID에 SQL 조건·DROP 구문 주입 | `NOT_FOUND`, 정책 테이블 및 레코드 유지 |
| S4 | `shell`, `exec`, `fetch_url` Tool로 시스템 명령 요청 | 3개 모두 `INVALID_TOOL_ARGUMENTS`, 프로세스 실행 없음 |
| S5 | 동일 이벤트 10개 동시 재전송 후 같은 ID의 내용 변조 | 입력 버전 1회 증가, 변조는 `EVENT_CONFLICT` |

10건은 해당 코드 경로의 검증 결과다. 모든 공격, 모델 프롬프트 주입, DDoS 또는 200명 동시 구매에 대한 안전 보장이 아니다. 기존 PostgreSQL 테스트에서는 중복 승인·Worker 실행 후 영수증/차감 1회도 별도로 통과했다.

## UX 평가 및 수정

| 항목 | 관찰/조치 |
|---|---|
| 설치 | Android Chrome·Windows Edge용 manifest, 192/512 PNG, standalone, 설치 버튼/미지원 브라우저 안내 추가 |
| PC·모바일 | 1440×1000, 390×844에서 구매·로그인·회원가입 확인. 가로 넘침 없음, 주요 터치 대상 44px 이상 |
| 설치 안내 | 모달 열기·닫기·Escape·버튼 포커스 복귀 확인. 모달에 접근성 제목 연결 추가 |
| 페이지 이동 | 로그인·회원가입과 정책·기록의 문서 제목 및 제목 포커스 보완. 최신 배포에서 정책/기록 키보드 전환 후 H1 활성과 문서 제목, 설치 모달 접근성 이름 재확인 |
| 오프라인 | 연결 끊김 안내·별도 오프라인 화면. API/계정/주문 데이터를 서비스 워커에 저장하지 않고 쓰기 요청을 큐잉·재전송하지 않음 |
| 가입 진입 | SMTP 미설정으로 회원가입 제출 비활성. 일반 신규 사용자의 진입을 막는 미해결 사항 |
| 구매 계획 | 범용 요청 입력은 가능하지만 복합 프로젝트를 단일 품목으로 축약하는 모델 행동이 관찰됨. 현재 다품목 발주용 UX로는 부족 |
| 가격 입력 | 실제 검색 가격이 미확인인 경우 사용자 모의 단가 입력 필요. 자동 실견적처럼 보이지 않도록 구분 유지 |

- Android 실기기 및 Windows OS 설치 창에서 설치 완료·재실행은 **미검증**이다. APK/MSIX 또는 스토어 패키지를 만든 것은 아니다. 브라우저 manifest 파싱 오류 없음과 반응형 UI를 검증했다.
- 서비스 워커 보안 동작은 배포 파일을 가져와 격리 실행해 검증했다. 실제 브라우저 오프라인 전환·SW 활성화 상태는 별도 미검증이다.
- 설치 방식 참조: [Microsoft Edge PWA 사용](https://learn.microsoft.com/en-us/microsoft-edge/progressive-web-apps/ux), [Chrome 설치 조건](https://web.dev/articles/install-criteria).

## 턴키 실행

| 목적 | 실행 |
|---|---|
| 일반 사용자 | 루트 `start-app.cmd` 더블클릭. Node/Python/DB 설치 없이 온라인 앱 열기 |
| 연결 확인 후 앱 열기 | `npm run app` (Node 24 필요) |
| 연결 확인만 | `npm run app:check` |
| 개발 서비스 일괄 시작 | `.env`와 의존성·DB 마이그레이션 준비 후 `npm run dev:all` |
| 공격 10건 재검증 | `npm run qa:requested` |
| Kiln·DDGS 실제 호출 포함 | `npm run qa:requested:live` — 실제 키 및 비공개 `.test-state/supabase-runtime.json` 필요, 호출 비용 발생 |
| 배포된 PWA 파일 검증 | `npm run qa:pwa` |
| Vercel 재배포 | 프로젝트 연결·환경변수 설정 후 `npm run deploy:app` |

- `dev:all`은 검색·거래 API·정책 API·Vite를 한 번에 실행하고 준비 상태를 확인한다. Ctrl+C 또는 자식 서비스 실패 시 자신이 만든 프로세스만 종료한다. 기존 포트를 점유한 프로세스는 죽이지 않는다.
- 누락된 인증/DB 값은 이름만 출력하고 종료한다. DB 초기화, 기존 비밀번호 변경, 정책/모의 잔고 자동 생성은 하지 않는다.
- 개발 검증은 별도 DB 역할과 포트 55600–55603으로 실제 4개 서비스를 기동해 통과했다. 검색/API/정책/UI health, Vite API 프록시, 미인증 요청 401 확인. 기본 `.env`는 `DATABASE_POLICY_URL`, `AUTH_TOKEN_HASHES`가 없어 정상적으로 사전 차단됐다.
- 동일 OS 계정에서 실행하는 개발 스택은 운영 권한 격리를 대체하지 않는다. 감사 signer는 이 스크립트에서 켜지 않으며 별도 보안 호스트에 둔다.
