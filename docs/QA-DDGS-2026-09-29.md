# DDGS 검색 연동 QA

## 선택과 계약
- GitHub: https://github.com/deedy5/ddgs (MIT), PyPI ddgs 9.16.0.
- 비교 후보 SearXNG: https://github.com/searxng/searxng. 현재 Docker 엔진 미실행으로 Python에서 직접 운영 가능한 DDGS 채택.
- 실제 모델 설정: Kiln qwen3-32b. 검색은 모델 기능이 아니라 Node의 search_products Tool Calling이 로컬 DDGS API를 호출한다.
- Brave API 키 없이 DDGS의 DuckDuckGo, Brave, Google, Mojeek, Startpage, Yahoo 엔진을 서버가 각각 조회한다. 모델/사용자는 backend를 변경할 수 없다.
- SEARCH_API_URL은 http://127.0.0.1:4479. 공개 인터넷에 검색 서버를 노출하지 않는다.

## 검증
- 실제 한국어 검색: DDGS 라이브러리 5개, 로컬 HTTP API 10개 결과. 쿠팡·G마켓 등의 실제 검색 제목과 URL 확인.
- Computer Use: 구매 화면에서 요청 생성→실제 Qwen 재개→검색 후보 10개 표시 확인. 테스트 fixture로 만든 후보가 아니다. 최종 재실행에서 조건·정책 예시·실제 후보 10개 표시까지 확인했다. 스크린샷 ddgs-qwen-candidates.png를 보관했다.
- 실제 실행에서 SEARCH_SCOPE_MISMATCH 발견: 범위 검사 유지, 도구 명세와 제한된 재교정 추가. 회귀 테스트로 교정 후 제공자 미설정 오류에서 종료 확인.
- 수집 허용 목록의 누락을 모델이 정책 차단이라고 오해하는 문제 발견: 후보가 있고 모의 금액이 없을 때 서버가 정해진 모의 금액 입력 안내를 반환하도록 수정. 회귀 테스트 추가.
- cross-site Origin 요청 403, 추출 API 404, backend 변경 요청 422, 8KB 초과 요청 413 확인.
- Node 11개 + Python 정책 평가 8개 통과. 전체 build 통과. Python pip check 통과.
- 같은 query/page는 최대 256개 메모리 캐시에 저장한다. 정상 결과는 60초, 빈/partial 결과는 5초 유지한다. 동시 검색 질의는 2개로 제한하며 동일 검색은 진행 중 작업을 병합한다.

## 2026-09-30 보강 및 반복 검색
- Qwen이 첫 tool call을 놓쳐 원문 검색이 생략되지 않도록 원문 질의를 서버가 먼저 검색한 뒤 LangChain 에이전트에 결과를 전달한다. 서로 다른 엔진의 실패는 빈 결과로 위장하지 않고 partial/error로 유지한다.
- 검색 에이전트에는 현재 허용 호스트를 알려주고, `site:` 변형은 해당 목록으로 제한한다. 모델이 검색 결과에서 본 외부 호스트를 임의로 따라가는 일은 막는다.
- DDGS 설치본이 노출하는 검색 엔진을 확인해 지원하지 않는 Bing 호출을 제거하고 여섯 텍스트 엔진을 개별 병렬 조회하도록 바꿨다. 한 엔진 오류가 다른 엔진의 정상 결과를 버리지 않으며, 빈 결과·partial 응답은 5초 캐시한다.
- 로컬 검색 API와 Vercel `/api/compute`가 같은 `search_service/providers.py`를 사용하게 했다. 앞선 backend 응답 계약 불일치를 제거하고, 배포 산출물에 공용 검색 모듈을 포함한다.
- `TAVILY_API_KEY`가 있으면 Tavily Search를 사용하고 없으면 DDGS 경로를 사용하도록 선택 provider를 연결했다. 현재 환경에는 Tavily·Kiln 키가 없어 해당 API와 Qwen tool call은 실호출되지 않았다.
- 실제 SearchService 반복 조회: `IKEA BILLY bookcase 80x28x202 white Korea KRW`는 discovery 8건, 승인 호스트 후보 5건, HTML 관측 3건/가격 3건을 반환했다. 배송비 관측은 0건이라 구매 견적으로 사용할 수 없다.
- 공유 provider 모듈의 실제 반복 조회에서 `IKEA BILLY bookcase 80x28x202`는 `BILLY Bookcase - white 80x28x202 cm`, IKEA 브랜드, 49.99 EUR로 파싱됐다. KRW 정책 통화와 배송비가 없어 구매 견적으로 사용할 수 없으며, 같은 질의의 직후 재시도는 `SEARCH_UNAVAILABLE`이어서 공급자 재현성은 미달이다.
- 최신 `site:ikea.com BILLY bookcase 80x28x202 white Korea KRW` 실행은 부분 결과(discovery 8, 승인 호스트 8, 후보 10, HTML 관측/가격 6, 배송비 0)를 반환했으며 즉시 재실행은 `SEARCH_UNAVAILABLE`이었다. 관측 후보의 상품명 관련성 및 반복 재현성은 아직 입증되지 않았다.
- `Logitech MX Master 3S wireless mouse Korea KRW`, `iPad Air M3 11 inch Korea KRW`는 반복 실행 시 상위 엔진이 결과 또는 정상 응답을 주지 않아 `SEARCH_UNAVAILABLE`로 종료했다. 무결과로 표시하거나 후보를 생성하지 않았다.
- 이번 체크아웃에는 Kiln API 키·모델 및 `SEARCH_API_URL` 설정이 없어 Qwen 호출과 전체 에이전트 반복은 재검증하지 못했다. TypeScript build와 Python syntax check는 통과했다. 테스트 스위트는 실행하지 않았다.
- DDGS 9.16.0 설치본의 텍스트 엔진을 직접 확인해 Bing이 없음을 확인했다. 수정 후 IKEA 질의를 엔진별로 실행했을 때 DuckDuckGo 3건, Yahoo 7건을 반환했고 Brave·Google·Mojeek·Startpage는 정상 빈 결과였다.
- 전체 provider 반복 검색은 여전히 안정적이지 않았다. 같은 IKEA 질의가 `SEARCH_UNAVAILABLE`과 해외 IKEA 페이지 위주 partial 결과로 갈렸고, 11번가 Galaxy Buds 질의는 관련 없는 상품 페이지를 섞었다. 따라서 반복 재현성과 검색 정밀도는 통과로 간주하지 않는다.
- `site:www.ikea.com/kr/ko`처럼 승인 호스트 안의 시장 경로를 허용하고, Tavily에는 한국어/원화 검색의 한국 지역 신호를 추가했다. Kiln/Tavily 자격증명이 없어 에이전트와 Tavily 실호출은 검증하지 못했다.
- 지역 경로 검색은 IKEA 한국어 상품 페이지를 상위로 반환했다. 앱의 SSRF 보호 수집기와 JSON-LD parser로 `BILLY 빌리 책장 - 화이트 80x28x202 cm`, `89,900 KRW`를 확인했으나 배송비 근거가 없어 주문 견적에는 사용할 수 없다.
- 11번가 Galaxy Buds3 질의의 실제 두 상품 페이지는 토트백과 수경이었다. 둘 다 `Buds3` 모델 anchor가 없으므로 새 서버 relevance gate에서 최종 후보로 저장하지 않는다.
- 후속 반복에서 영어 전용 `site:www.11st.co.kr Galaxy Buds3 Pro`는 Buds2 및 무관 후보를 섞었지만, `site:www.11st.co.kr Samsung Galaxy Buds3 Pro 삼성 갤럭시 버즈3 프로`는 Buds3 Pro 판매 결과를 반환했다. SSRF 보호 페이지 수집/parser로 실제 11번가 페이지 3개를 다시 확인해 `삼성전자 갤럭시 버즈3 프로` 상품명, 248,880~399,000 KRW 가격 및 무료배송 표시를 읽었다. 검색 정밀도는 한국어 병기 쿼리에서 개선됐으나, 검색엔진의 같은 쿼리 반복 안정성은 여전히 보장하지 않는다.
- 이 사례에서 영어 `Buds3` 전체 단어 일치만 강제하면 한국어 `버즈3`를 놓칠 수 있음을 확인했다. 관련성 선택은 LangChain Qwen 에이전트가 후보 ID를 반환하게 하고, 서버는 `3` 숫자 서명을 계속 강제하도록 보완했다. Kiln 키·모델 설정이 없어 이번 후보 ID 선택 단계의 Qwen 실호출은 검증하지 못했다.

## 2026-09-30 직접 판매처 검색 추가 검증
- UTF-8로 재실행한 DDGS 실제 provider 조회에서 `site:www.11st.co.kr Samsung Galaxy Buds3 Pro 삼성 갤럭시 버즈3 프로`는 부분오류 없이 엉뚱한 상위 상품을 냈고, 같은 질의 재실행·한국어 전용 질의·영어 전용 질의는 `SEARCH_UNAVAILABLE`로 끝났다. 같은 제품을 반복 검색할 때 DDGS만으로는 정밀도와 재현성이 부족했다.
- 승인 호스트에 `www.11st.co.kr`이 있을 때 11번가 자체 검색 페이지를 보조 검색원으로 연결했다. `삼성 갤럭시 버즈3 프로`를 실제 두 번 조회해 동일한 상품 목록을 받았고, 상품 ID/제목만 읽어 고정된 `www.11st.co.kr/products/<id>` 주소를 만든다. 검색 페이지의 표시 가격·배송값은 근거로 사용하지 않는다.

- 현재 체크아웃에는 `KILN_API_KEY`, `KILN_MODEL`, `SEARCH_API_URL`, `TAVILY_API_KEY`가 설정되지 않았다. 로컬 Python DDGS API를 별도로 띄워 SearchService 연동은 확인했지만, 실제 Kiln/Qwen tool-call과 후보 ID 선택은 아직 미검증이다. 자동 테스트는 실행하지 않았다.

## 2026-09-30 후보 선택 호출 보강
- 이 브랜치는 이미 `langchain`의 `createAgent`와 `@langchain/openai`의 `ChatOpenAI`로 Kiln OpenAI 호환 API를 호출한다. [Kiln 모델 표](https://kiln.bricksum.com/docs/en/models)에서 `qwen3-32b`는 자동 tool calling은 지원하지만 강제 tool choice와 병렬 tool call은 지원하지 않아, 같은 Kiln/Qwen 구성과 자동 tool choice를 유지한다. [Kiln API 문서](https://kiln.bricksum.com/docs/en/api-reference)는 JSON `response_format`을 아직 지원하지 않는다고 명시한다.
- 기존 구현은 마지막 자유 형식 JSON을 정규식으로 읽었고, 파싱/검증 실패 시 후보 ID 선택 없이 숫자 anchor만 맞는 후보까지 통과시켰다. 이를 `select_relevant_candidates` 필수 도구 호출로 바꿨다. 제출 ID는 실제 검색 후보와 대조하고, 미선택/미등록 ID면 `SEARCH_SELECTION_MISSING`으로 종료한다.
- 후보 이름에 모델 번호만 맞는 단품·액세서리·중고·벌크 매물이 섞이는 것을 확인해, 요청 범위가 완제품일 때 판매 단위도 검사하도록 에이전트 지침을 보강했다.
- 이 변경은 정밀도 우선의 보수적 동작을 만든다. 실제 Kiln 키가 없어 새 도구 호출과 Qwen의 단품/세트 구분은 라이브 검증 전이다.

## 2026-09-30 IKEA first-party 검색 보강
- IKEA 한국 페이지의 공개 스크립트에서 사이트 내부 검색 서비스 주소와 요청 형식을 확인했다. BILLY 검색을 실제 호출해 상품명, 치수, 공식 상세 URL을 받았고, exact query에서는 `BILLY 빌리 책장 - 화이트 80x28x202 cm` 상세 페이지가 반환됐다. 검색 API 가격은 후보 근거로 쓰지 않는다.
- 서버는 HTTPS, DNS public-IP 검사 및 고정 연결, 정적 호스트·경로, JSON 유형, 2 MiB 응답 제한, 10초 제한을 적용한다. 반환 URL은 다시 승인된 IKEA 상세 페이지로만 수집하며 최종 가격/배송은 상세 HTML Product 자료에서만 읽는다.
- 캐시 없는 새 `SearchService` 인스턴스로 `site:www.ikea.com/kr/ko BILLY 빌리 책장 80x28x202 화이트`를 두 번 실행했다. 두 번 모두 단일 후보 `BILLY 빌리 책장, 화이트, 80x28x202 cm`를 반환했고 동일 IKEA 상세 페이지에서 `HTML_OBSERVATION`, `www.ikea.com`, 89,900 KRW를 확인했다. 배송은 페이지 근거가 없어 `null`로 유지됐다.
- 더 넓은 `site:www.ikea.com/kr/ko BILLY 빌리 책장`은 첫 두 페이지에서 각각 9개 후보를 반환하고 다음 페이지 커서를 제공했다. 첫 페이지에는 흰색 80x28x202 외에 40x28x202, 80x28x106 등 다른 크기도 함께 있어, exact dimensions 유지와 후보 선택이 필요함을 확인했다.
- `productIdentityConflicts` 서버 후검사를 추가했다. 원문 치수 tuple, 하나만 지정된 색상, 한쪽 유닛·교체품·단독 케이스/충전 액세서리·호환·중고·벌크 표기를 비교한다. 정확한 BILLY 요청 조건으로 넓은 첫 페이지 후보 9개를 다시 분류했을 때 80x28x202만 통과했고, 다른 8개 규격은 `dimension_mismatch`였다.
- 블랙 참나무무늬 BILLY `80x28x202` 검색을 두 번 실행해 같은 제품명과 99,900 KRW를 재현했다. 이 상품은 블랙/참나무 마감으로 정확히 요청하면 통과하고, 흰색 요청과 비교하면 `color_mismatch`로 차단됐다. `site:www.ikea.com/kr/ko` 경로의 `/`가 색상 선택 기호로 오인되지 않도록 옵션 판정 전에 site filter를 제거했다.
- 같은 SM-R630N 11번가 실검색도 캐시 없는 인스턴스로 두 번 실행했다. 두 회차 모두 같은 10개 결과 순서가 나왔다. 정식 흰색 완제품 후보 4개는 치수/판매 단위 후검사를 통과했고, 오른쪽·왼쪽 단품, 한쪽 구매, 본체 케이스, 충전품 후보 6개는 `sale_form_mismatch`로 걸렸다. 정식 판매 페이지에서 252,110/255,000/247,790 KRW와 무료배송 근거를 읽었다.
- 두 판매처를 함께 허용한 기본 경로에서도 버즈와 BILLY 질의를 각각 두 번 실행해 같은 10개 결과를 재현했다. 버즈 검색은 11번가 후보 10개 중 위의 완제품/부품 분류가 동일했고, IKEA의 정상적인 빈 결과 때문에 전체 부분오류가 되지 않았다. BILLY 검색은 11번가의 규격 불일치 9개와 IKEA의 정확한 80x28x202 상품 1개를 반환했다.
- 혼합 버즈 검색 첫 실행에서 IKEA API의 정상 `200 results:[]` 응답을 서버가 형식 오류로 잘못 처리하는 문제를 발견했다. 빈 결과를 정상 성공으로 처리하고, 모든 호출이 빈 결과일 때도 검색 실패와 구분하도록 수정했다. 이후 혼합 반복 검색은 `partial: false`, `providerFailures: []`였다.
- 일반 검색 provider가 없는 경우, 허용 호스트가 11번가/IKEA의 직접 검색만으로 구성돼 있으면 설정되지 않은 DDGS provider를 실패로 세지 않도록 조정했다. 수정 후 11번가와 IKEA 반복 검색 모두 `partial: false`, provider 실패 없음으로 응답했다. 다른 허용 도메인의 일반 검색은 여전히 `SEARCH_API_URL` 또는 Tavily 설정이 필요하다.
- backend TypeScript 빌드가 통과했다. 현재 checkout에는 `KILN_API_KEY`가 없어 Qwen/LangChain 후보 선택의 라이브 단계는 실행할 수 없었다. IKEA 검색 API는 공식 개발자 문서가 없는 사이트 내부 인터페이스여서 요청 구조나 주소 변경 시 실패할 수 있다.
