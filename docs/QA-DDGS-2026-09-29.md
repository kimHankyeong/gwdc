# DDGS 검색 연동 QA

## 선택과 계약
- GitHub: https://github.com/deedy5/ddgs (MIT), PyPI ddgs 9.16.0.
- 비교 후보 SearXNG: https://github.com/searxng/searxng. 현재 Docker 엔진 미실행으로 Python에서 직접 운영 가능한 DDGS 채택.
- 실제 모델 설정: Kiln qwen3-32b. 검색은 모델 기능이 아니라 Node의 search_products Tool Calling이 로컬 DDGS API를 호출한다.
- Brave API 키 없이 DDGS의 DuckDuckGo, Brave, Google, Mojeek, Startpage, Yahoo 엔진을 서버가 각각 조회한다. 모델/사용자는 backend를 변경할 수 없다.
- SEARCH_API_URL은 http://127.0.0.1:4479. 공개 인터넷에 검색 서버를 노출하지 않는다.

## 검증
- 실제 한국어 검색: DDGS 라이브러리 5개, 로컬 HTTP API 10개 결과. 쿠팡·G마켓 등의 실제 검색 제목과 URL 확인.
- Computer Use: 구매 화면에서 요청 생성→실제 Qwen 재개→검색 후보 10개 표시 확인. 테스트 fixture로 만든 후보가 아니다. 최종 재실행에서 조건·정책 예시·실제 후보 10개 표시까지 확인했다. 스크린샷 ddgs-qwen-candidates.png를 보관했다.
- 실제 실행에서 SEARCH_SCOPE_MISMATCH 발견: 범위 검사 유지, 도구 명세와 제한된 재교정 추가. 회귀 테스트로 교정 후 제공자 미설정 오류에서 종료 확인.
- 수집 허용 목록의 누락을 모델이 정책 차단이라고 오해하는 문제 발견: 후보가 있고 모의 금액이 없을 때 서버가 정해진 모의 금액 입력 안내를 반환하도록 수정. 회귀 테스트 추가.
- cross-site Origin 요청 403, 추출 API 404, backend 변경 요청 422, 8KB 초과 요청 413 확인.
- Node 11개 + Python 정책 평가 8개 통과. 전체 build 통과. Python pip check 통과.
- 같은 query/page는 최대 256개 메모리 캐시에 저장한다. 정상 결과는 60초, 빈/partial 결과는 5초 유지한다. 동시 검색 질의는 2개로 제한하며 동일 검색은 진행 중 작업을 병합한다.

## 2026-09-30 보강 및 반복 검색
- Qwen이 첫 tool call을 놓쳐 원문 검색이 생략되지 않도록 원문 질의를 서버가 먼저 검색한 뒤 LangChain 에이전트에 결과를 전달한다. 서로 다른 엔진의 실패는 빈 결과로 위장하지 않고 partial/error로 유지한다.
- 검색 에이전트에는 현재 허용 호스트를 알려주고, `site:` 변형은 해당 목록으로 제한한다. 모델이 검색 결과에서 본 외부 호스트를 임의로 따라가는 일은 막는다.
- DDGS 설치본이 노출하는 검색 엔진을 확인해 지원하지 않는 Bing 호출을 제거하고 여섯 텍스트 엔진을 개별 병렬 조회하도록 바꿨다. 한 엔진 오류가 다른 엔진의 정상 결과를 버리지 않으며, 빈 결과·partial 응답은 5초 캐시한다.
- 로컬 검색 API와 Vercel `/api/compute`가 같은 `search_service/providers.py`를 사용하게 했다. 앞선 backend 응답 계약 불일치를 제거하고, 배포 산출물에 공용 검색 모듈을 포함한다.
- `TAVILY_API_KEY`가 있으면 Tavily Search를 사용하고 없으면 DDGS 경로를 사용하도록 선택 provider를 연결했다. 현재 환경에는 Tavily·Kiln 키가 없어 해당 API와 Qwen tool call은 실호출되지 않았다.
- 실제 SearchService 반복 조회: `IKEA BILLY bookcase 80x28x202 white Korea KRW`는 discovery 8건, 승인 호스트 후보 5건, HTML 관측 3건/가격 3건을 반환했다. 배송비 관측은 0건이라 구매 견적으로 사용할 수 없다.
- 공유 provider 모듈의 실제 반복 조회에서 `IKEA BILLY bookcase 80x28x202`는 `BILLY Bookcase - white 80x28x202 cm`, IKEA 브랜드, 49.99 EUR로 파싱됐다. KRW 정책 통화와 배송비가 없어 구매 견적으로 사용할 수 없으며, 같은 질의의 직후 재시도는 `SEARCH_UNAVAILABLE`이어서 공급자 재현성은 미달이다.
- 최신 `site:ikea.com BILLY bookcase 80x28x202 white Korea KRW` 실행은 부분 결과(discovery 8, 승인 호스트 8, 후보 10, HTML 관측/가격 6, 배송비 0)를 반환했으며 즉시 재실행은 `SEARCH_UNAVAILABLE`이었다. 관측 후보의 상품명 관련성 및 반복 재현성은 아직 입증되지 않았다.
- `Logitech MX Master 3S wireless mouse Korea KRW`, `iPad Air M3 11 inch Korea KRW`는 반복 실행 시 상위 엔진이 결과 또는 정상 응답을 주지 않아 `SEARCH_UNAVAILABLE`로 종료했다. 무결과로 표시하거나 후보를 생성하지 않았다.
- 이번 체크아웃에는 Kiln API 키·모델 및 `SEARCH_API_URL` 설정이 없어 Qwen 호출과 전체 에이전트 반복은 재검증하지 못했다. TypeScript build와 Python syntax check는 통과했다. 테스트 스위트는 실행하지 않았다.
- DDGS 9.16.0 설치본의 텍스트 엔진을 직접 확인해 Bing이 없음을 확인했다. 수정 후 IKEA 질의를 엔진별로 실행했을 때 DuckDuckGo 3건, Yahoo 7건을 반환했고 Brave·Google·Mojeek·Startpage는 정상 빈 결과였다.
- 전체 provider 반복 검색은 여전히 안정적이지 않았다. 같은 IKEA 질의가 `SEARCH_UNAVAILABLE`과 해외 IKEA 페이지 위주 partial 결과로 갈렸고, 11번가 Galaxy Buds 질의는 관련 없는 상품 페이지를 섞었다. 따라서 반복 재현성과 검색 정밀도는 통과로 간주하지 않는다.
- `site:www.ikea.com/kr/ko`처럼 승인 호스트 안의 시장 경로를 허용하고, Tavily에는 한국어/원화 검색의 한국 지역 신호를 추가했다. Kiln/Tavily 자격증명이 없어 에이전트와 Tavily 실호출은 검증하지 못했다.
- 지역 경로 검색은 IKEA 한국어 상품 페이지를 상위로 반환했다. 앱의 SSRF 보호 수집기와 JSON-LD parser로 `BILLY 빌리 책장 - 화이트 80x28x202 cm`, `89,900 KRW`를 확인했으나 배송비 근거가 없어 주문 견적에는 사용할 수 없다.
- 11번가 Galaxy Buds3 질의의 실제 두 상품 페이지는 토트백과 수경이었다. 둘 다 `Buds3` 모델 anchor가 없으므로 새 서버 relevance gate에서 최종 후보로 저장하지 않는다.

## 구분할 한계
- 검색 결과는 상품 신원/가격 검증이 아니다. SOURCE_ALLOWED_HOSTS가 비어 있으므로 이번 브라우저 QA는 검색 제목·URL까지만 검증했고 원문 가격·평점은 미확인으로 표시했다.
- 배송비/단가는 사용자가 정하는 모의 입력이다. 검색 실패·원문 누락을 모델 생성 정보로 채우지 않는다.
- 상위 검색 엔진의 차단·검색 품질·트래픽 제한에 영향을 받는다. CAPTCHA나 차단을 우회하지 않는다. 5000명/200명 동시 실검색 SLA는 미검증이다.
- Sepolia 서명 지갑과 테스트 ETH가 아직 준비되지 않아 실제 감사 전체 QA는 미완료다. 검색 연동 성공을 체인 성공으로 표시하지 않는다.
